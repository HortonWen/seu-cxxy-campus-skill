# 用 Python 逆向并自动化我学校的几个老旧系统

起因很简单：学校发了一个人工智能算法竞赛的校赛通知，报名截止只剩几天。我想看看现在有哪些比赛能报名、自己的课表和成绩在哪查，结果被几个"上古"系统折腾得不轻——于是干脆用 Python 把它们自动化了。

## 摸清系统结构

先把学校相关的系统捋了一遍：

| 系统 | 技术栈 | 登录 |
|---|---|---|
| 官网 | 静态页 + 列表页 | 无需登录 |
| 学科竞赛管理系统 | ASP.NET WebForms（GBK） | 学号 + 密码 |
| 数字校园门户 | Java 门户（UTF-8） | 校园卡号 + 密码 |
| 教务系统（旧） | 金智 epstar，只认 IE | 门户 SSO |
| 教务系统（新·师生服务端） | jQuery + ligerUI | 门户 SSO |

有意思的是：同一所学校同时跑着两套教务系统，一套老得只认 IE 内核，一套是相对现代的网页应用——但入口藏在门户的「学习服务」里，很多人点成了老的「教务系统」，所以 Chrome/Edge 打不开。

## 逆向登录流程

### 竞赛系统：ASP.NET WebForms

经典套路，但细节不少：

1. `GET index.aspx`，拿到 `__VIEWSTATE`、`__VIEWSTATEGENERATOR`、`__EVENTVALIDATION`。
2. `POST index.aspx`，带 `UserId`、`Pwd` 和图片按钮的坐标 `Append.x/y`。
3. 成功后在返回的 JS 里抓 `location.href='Main/Main.aspx?sid=...&screen=...'`。
4. 之后的每个请求都要带着 `sid` 和 `screen`。
5. 列表翻页是 `__doPostBack('btnNext','')`：把页面所有表单字段原样 POST 回去。

页面编码是 GBK，解码别用错，否则全是乱码。

### 门户：SSO 单点登录

门户登录 POST `userPasswordValidate.portal`，带 `Login.Token1`、`Login.Token2`，成功后下发 `iPlanetDirectoryPro` Cookie。这个 Cookie 对 `*.cxxy.seu.edu.cn` 全子域生效，于是能直接单点登录进教务系统——不需要再单独登录。

## 卡壳的地方：IE-only 的老教务系统

自动化到成绩和课表时卡住了。老教务系统是金智 epstar 那套很老的 JS 应用，成绩、课表这些数据靠**动态菜单 + 模板接口**加载：

- 登录本身能通过门户 SSO 解决；
- 但数据接口是数据库动态生成的，没有固定 URL，用脚本硬扒既慢又不稳；
- 更麻烦的是它只认 IE 内核，普通浏览器直接打不开。

最后的选择是：

1. 换到**新教务系统**（师生服务端），从门户「学习服务」进去，现代浏览器能正常开，成绩 / 课表在它的菜单里；
2. 实在要用老系统，就开 **Edge 的 IE 模式**加载。

这也印证了一个经验：老系统的坑经常不在「登录」，而在「登录之后的数据加载方式」。

## 写成脚本，零依赖

三个脚本，全用 Python 标准库（`urllib` + `http.cookiejar`），不用装任何第三方包：

- `website.py`：抓官网通知、按关键词搜索、拿竞赛目录。
- `competition.py`：竞赛系统登录、列出可报名项目、查已报名、看项目详情。
- `portal.py`：门户登录、读身份信息、SSO 进新旧教务系统。

关键原则：**账号密码一律由使用方临时传入，绝不写进代码或日志**。凭据只走内存和标准输入。

## 打包成 Codex skill

按 Codex 的 skill 规范组织成 `SKILL.md + scripts/ + references/`，放进 `~/.codex/skills/`。以后一句话就能触发，比如「查一下现在能报名的比赛」。

## 开源

代码已经开源（MIT 协议），仓库里不含任何账号、密码、学号、令牌——这是硬约束。

## 几点心得

1. 老系统打不开浏览器，往往在 HTTP 层直接调更快，绕开浏览器兼容性。
2. 自动化边界要清楚：只操作自己的账号、不越权、不批量、不碰别人数据。
3. 凭据「用完即弃」，别图省事写进脚本。
